# 01. LLM 동작 흐름, 토크나이저, 그리고 Transformer 내부 구조

> **Phase 1 (1-4주)** 산출물 — "프롬프트 한 줄이 답변이 되기까지" 내부에서 벌어지는 일을 직관적으로 이해하고, 보안 점검 관점의 핵심 포인트를 정리합니다.

## 0. 큰 그림: `"현재 시간 알려줘"`를 입력했을 때 내부에서 벌어지는 5단계

1. **토크나이징 (입력 인코딩)**: 문자열 `"현재 시간 알려줘"`를 모델이 읽을 수 있는 정수 ID 배열(예: `[264, 512, 881]`)로 변환합니다.
2. **임베딩 및 Transformer 연산 (의미 파악)**: 각 숫자를 고차원 벡터로 바꾸고, Attention으로 단어 간 문맥을 계산해 "다음에 올 가장 그럴듯한 토큰"의 점수표(**Logit**)를 출력합니다.
   - 참고: 순수 LLM 자체는 시스템 시계에 접근할 수 없어 실시간 시간을 모릅니다. 실제 서비스에서는 시스템 프롬프트에 현재 시간을 주입하거나, 모델이 `get_time()` 같은 도구 호출(Tool Call)을 출력해 외부 시스템에서 시간을 받아옵니다.
3. **샘플링 (다음 토큰 선택)**: 점수표(Logit)를 확률로 바꾼 뒤 Temperature / Top-k / Top-p 규칙에 따라 토큰 1개(예: `"지금"`)를 선택합니다.
4. **반복 생성 (Autoregressive 루프)**: 선택된 토큰을 다시 입력 맨 뒤에 붙여 1-3단계를 반복하며, 종료 토큰(EOS)이 나올 때까지 답변을 한 토큰씩 이어 붙입니다.
5. **로컬 추론 최적화 (`llama.cpp`)**: 이전 토큰 계산 결과를 메모리(KV Cache)에 재사용하고, 모델 가중치를 압축(GGUF/INT4)해 제한된 VRAM에서 빠르게 실행합니다.

## 1. BPE 토크나이저 원리 (`01-mini-gpt/tokenizer.py`)

LLM은 문자열을 직접 이해하지 못하고 **정수(Token ID) 시퀀스**만 입력으로 받습니다. 현대 LLM(GPT-2, GPT-4, Llama 3 등)은 **Byte-level BPE (Byte Pair Encoding)** 방식을 사용합니다.

### 왜 Byte-level(UTF-8 바이트 기반)인가?
- 단어 단위(Word-level)로 사전을 만들면 처음 보는 신조어·오타·다국어가 들어올 때 `<UNK>`(Unknown) 토큰으로 뭉개져 정보가 완전히 사라집니다.
- 모든 텍스트를 UTF-8 바이트(`0`부터 `255`까지 총 256개 기본 토큰)로 분해해서 시작하면, **영어·한글·특수문자·이모지 어떤 문자열도 `<UNK>` 없이 100% 복원 가능**합니다.

### 오타가 발생해도 제대로 답변하는 원리
예를 들어 `"현재 시긴 알려줘"`처럼 오타가 들어와도 LLM이 정상적으로 답하는 이유는 두 단계가 결합되어 동작하기 때문입니다.
1. **토크나이저 단계 (정보 손실 방지)**: `"시긴"`이 사전에 통째로 없더라도 `<UNK>`로 버리지 않고, 더 작은 서브워드나 바이트 조각(`"시"`, `"긴"`)으로 쪼개어 모델에 그대로 전달합니다.
2. **Transformer 문맥 복원 단계**: 모델은 사전학습 과정에서 수많은 오타·줄임말과 앞뒤 문맥(`"현재"` + `"시..."` + `"알려줘"`)을 함께 학습했기 때문에, Self-Attention이 주변 단어와 결합해 `"시간"`과 거의 같은 의미 벡터로 해석해 냅니다.

### 보안 및 취약점 점검 관점 포인트
- **필터 우회 (Token Smuggling / 난독화)**: 입력 방화벽이나 키워드 필터는 정규 문자열(`"비밀번호"`, `"시스템 프롬프트"`)만 검사하지만, 공격자가 오타·특수문자 삽입·유니코드 변형을 섞으면 필터는 통과하고 LLM은 위 오타 복원 원리로 의도를 그대로 이해해 응답할 수 있습니다.
- **토큰 폭탄 (DoS / 비용 증가)**: 토크나이저가 잘 병합하지 못하는 희귀 문자나 깨진 바이트 패턴을 대량 입력하면, 짧은 문자열인데도 토큰 수가 비정상적으로 급증해 컨텍스트 윈도우와 KV Cache 메모리를 빠르게 고갈시킬 수 있습니다.

### 학습(Train)과 인코딩(Encode) 알고리즘
1. **학습 (`train`)**:
   - 전체 코퍼스를 UTF-8 바이트 ID 리스트로 변환합니다.
   - 인접한 토큰 쌍 `(a, b)`의 등장 빈도를 센 뒤, 가장 자주 나온 쌍을 새 토큰 ID(`256`, `257`, ...)로 치환합니다.
   - 이 과정을 `vocab_size - 256`번 반복하며 병합 규칙(`merges`)을 순서대로 기록합니다.
2. **인코딩 (`encode`)**:
   - 입력 문자열을 UTF-8 바이트로 변환한 뒤, 학습 시 **가장 먼저 만들어진 병합 규칙(가장 낮은 `new_id`)**부터 우선 적용해 시퀀스를 압축합니다.
3. **디코딩 (`decode`)**:
   - 각 토큰 ID를 원래 `bytes`로 치환해 이어 붙인 뒤 UTF-8로 디코딩합니다(`errors="replace"`로 불완전한 바이트 시퀀스 방어).

### `vocab_size`의 트레이드오프
- **`vocab_size`가 클수록**: 같은 문장을 더 적은 토큰 수로 압축(Context Window 효율 증가, 추론 속도 향상)할 수 있지만, `Token Embedding (V x D)` 및 `LM Head (D x V)` 가중치 행렬과 마지막 Softmax 연산 비용이 커집니다.
- **`vocab_size`가 작을수록**: 임베딩 파라미터는 줄어들지만 시퀀스 길이 `T`가 길어져 Attention 연산량($O(T^2)$)과 KV Cache 메모리가 급증합니다.

## 2. Decoder-only Transformer 아키텍처
- 입력 임베딩: `(B, T) -> (B, T, D)`
- **RMSNorm**: LayerNorm 대비 계산량 및 안정성 비교
- **RoPE (Rotary Position Embedding)**: 복소수 회전 행렬 기반 상대 위치 인코딩
- **GQA (Grouped-Query Attention)**:
  - Query: `(B, n_heads, T, head_dim)`
  - Key / Value: `(B, n_kv_heads, T, head_dim)`
  - KV Head 공유에 따른 KV Cache 절감 비율 정리
- **SwiGLU FFN**: 게이트 활성함수 구조 및 파라미터 수 계산

## 3. 텐서 차원 변화 표

| 레이어 / 연산 | 입력 Shape | 출력 Shape | 비고 |
| :--- | :--- | :--- | :--- |
| Token Embedding | `(B, T)` | `(B, T, D)` | `vocab_size x D` |
| Q Projection | `(B, T, D)` | `(B, n_heads, T, d_head)` | RoPE 적용 |
| K, V Projection | `(B, T, D)` | `(B, n_kv_heads, T, d_head)` | GQA 공유 |
| Attention Output | `(B, n_heads, T, d_head)` | `(B, T, D)` | Causal Mask 적용 |
| LM Head | `(B, T, D)` | `(B, T, V)` | Logits 출력 |
